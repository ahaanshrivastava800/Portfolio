Projects

GST Flow Demo

Solo demonstration project

Problem statement: Legacy GST filing systems process uploads synchronously; the request blocks and fails under load or with large files (10 s Vercel limit).

Solution architecture: One UI, two modes. Sync: POST /api/sync/upload blocks until completion or timeout. Async: POST /api/async/upload validates, queues the job in Upstash Redis and returns 202 with a job ID; a background worker endpoint (process-job) processes rows; the client tracks progress via polling and Server-Sent Events. A load simulator compares both modes under concurrent requests.

Tech stack: Next.js (App Router), React, Tailwind CSS, Upstash Redis (REST), Vercel serverless functions, Server-Sent Events

My contribution: Designed and built everything myself (solo).

Demonstration project on simulated GST data; load-test figures come from the built-in simulator.

CloudCode (prototype)

Built for the Omnikon National Hackathon 2026 (solo)

Problem statement: Coding on a phone is awkward: desktop editors are hard on small screens, symbols are buried on the keyboard, and work is lost when the connection drops.

Solution architecture: Next.js app with a CodeMirror editor, terminal-style output panel, snippet library and mobile accessory bar. JavaScript, Python (via Pyodide, WebAssembly) and SQL (via sql.js) are routed to a client-side Web Worker, with a timeout on each run; the Python and SQL runtimes are loaded from a CDN. C++, Rust, Go and Java go to /api/execute, which in this prototype returns SIMULATED output and does not compile or run code. Files, projects, execution logs and a sync queue use IndexedDB helpers, so work is stored locally in the browser; a service worker (next-pwa) provides PWA caching.

Tech stack: Next.js, React, CodeMirror, Web Workers, IndexedDB, next-pwa, Node.js

My contribution: Designed and built everything myself (solo).

Limitations: remote execution is simulated; no authentication or cloud database yet.
